# v0.1.0 Release Prerequisites — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Procure all signing keys, third-party accounts, and GitHub configuration required to publish `v0.1.0`; cut and verify the release on every supported platform.

**Architecture:** Mostly operational/procurement work plus minor code edits to swap dev keys with production keys and align the root workspace version. Many tasks are **human-only** (account creation, identity verification, web-UI configuration); these are clearly marked `[HUMAN]`. Tasks that an agent can execute are marked `[AGENT]`. Tasks marked `[HYBRID]` have an agent-executable component plus a human prerequisite (e.g., the human provides a public key, the agent commits the file).

**Tech Stack:** GPG (Curve25519 ECC), OpenSSL Ed25519, GitHub Actions, Cloudflare DNS, Azure DevOps (VS Code Marketplace PAT issuance), npm registry, Open VSX, GitHub repo settings.

**Source spec:** [`docs/superpowers/specs/2026-05-05-v0.1.0-release-readiness-design.md`](../specs/2026-05-05-v0.1.0-release-readiness-design.md) — Workstream A.

**Source runbook:** [`docs/release/v0.1.0-prerequisites.md`](../../release/v0.1.0-prerequisites.md). This plan executes the runbook with explicit verification gates.

## Task 2: Generate GPG signing key (offline)  `[HUMAN]`

**Why offline:** master key is never exposed to a CI machine. Only an export-only sign-capable subkey ships in GHA secrets.

**Files:**
- Output: `signing-subkey.asc` (kept locally, then loaded into GHA secret)
- Output: `public.asc` (will be committed in Task 3)

- [ ] **Step 1: Verify a recent GnuPG is installed**

Run on the offline machine: `gpg --version`
Expected: 2.2.0 or higher.

- [ ] **Step 2: Generate the master key**

Run: `gpg --expert --full-generate-key`

Answer prompts as follows:
- Key kind: `(11) ECC (set your own capabilities)`
- Toggle off Sign / Encrypt / Authenticate by entering `s`, `e`, `a` until only **Certify** remains.
- Confirm with `q`.
- Curve: `Curve 25519`
- Expiry: `0` (never)
- Real name: `Nimbus Release Signing`
- Email: `releases@nimbus-agent.dev`
- Comment: leave blank
- Passphrase: choose a strong one; record in your password manager under `nimbus-release-secrets`.

Expected: GnuPG prints `pub   ed25519 ... [C]` confirming a Certify-only master key.

- [ ] **Step 3: Add a Sign-only subkey**

Run:
```bash
gpg --edit-key releases@nimbus-agent.dev
```

In the gpg shell:
```
addkey
```
- Key kind: `(10) ECC (sign only)`
- Curve: `Curve 25519`
- Expiry: `2y`

Then:
```
save
```

Expected: `gpg --list-secret-keys` now shows `sec   ed25519 ... [C]` and `ssb   ed25519 ... [S]`.

- [ ] **Step 4: Export the public key and the signing subkey**

```bash
gpg --armor --export releases@nimbus-agent.dev > public.asc
gpg --armor --export-secret-subkeys releases@nimbus-agent.dev > signing-subkey.asc
```

Expected: two files created. `public.asc` starts with `-----BEGIN PGP PUBLIC KEY BLOCK-----`. `signing-subkey.asc` starts with `-----BEGIN PGP PRIVATE KEY BLOCK-----`.

- [ ] **Step 5: Record the long key fingerprint**

Run: `gpg --fingerprint releases@nimbus-agent.dev`

Copy the 40-character fingerprint (e.g., `ABCD 1234 ...`). Save it to `nimbus-release-secrets` in your password manager. You'll need it in Task 3 and on the SECURITY.md page.

- [ ] **Step 6: Publish the public key to a key server**

```bash
gpg --keyserver keys.openpgp.org --send-keys <fingerprint-no-spaces>
```

Expected: `gpg: sending key <KEYID> to ...` with no error.

- [ ] **Step 7: Back up the master key offline**

Copy the entire `~/.gnupg` directory to **two** USB drives stored in different physical locations. Then on the CI/dev machine: **delete the master key, keep only the subkey**:

```bash
gpg --export-secret-keys releases@nimbus-agent.dev > master-and-sub.bak
# Verify the backup is on USB before continuing.
gpg --delete-secret-keys releases@nimbus-agent.dev
gpg --import signing-subkey.asc
```

Expected: `gpg --list-secret-keys` shows `sec#` (greyed out, indicates secret-key not present) and `ssb` (subkey present).

## Task 4: Generate Ed25519 updater signing keypair (offline)  `[HUMAN]`

**Why use the existing script:** `scripts/sign-ed25519.ts` reads `process.env.UPDATER_SIGNING_KEY`, base64-decodes it, and rejects anything that isn't exactly 64 bytes. The existing helper at `scripts/generate-updater-keypair.ts` produces a secret in that exact format and writes it to a temp file with the right permissions. **Do not** generate the keypair with raw `openssl` — `openssl` produces a PEM file, which is the wrong format for this secret and will cause CI signing to fail.

**Files:**
- Modify: `packages/gateway/src/updater/public-key.ts` — manually reset the dev key to the placeholder so the script will run (its safety check refuses to overwrite a non-placeholder value).
- Output: a temp file at the path printed by the script, containing the base64 private key. This file is the input to `gh secret set UPDATER_SIGNING_KEY` in Task 6.

- [ ] **Step 1: Confirm the current public key value**

Run: `grep UPDATER_PUBLIC_KEY_BASE64 packages/gateway/src/updater/public-key.ts`
Expected: a line of the form:
```
export const UPDATER_PUBLIC_KEY_BASE64 = "<some-base64>";
```
If the value is `"<DEV-PLACEHOLDER>"`, skip to Step 3. Otherwise the current value is a previously-generated dev key — proceed to Step 2.

- [ ] **Step 2: Reset the constant to the placeholder so `generate-updater-keypair.ts` will run**

The script refuses to overwrite a non-placeholder public key (line 24-42 of `scripts/generate-updater-keypair.ts`). Manually edit `packages/gateway/src/updater/public-key.ts` and set:

```typescript
export const UPDATER_PUBLIC_KEY_BASE64 = "<DEV-PLACEHOLDER>";
```

**Do not commit this change yet** — it lives only on disk for one minute until Step 4 overwrites it.

- [ ] **Step 3: Generate the keypair on the offline machine**

```bash
bun scripts/generate-updater-keypair.ts
```

Expected output (paths and base64 values will differ):
```
Updater Ed25519 keypair generated.

PUBLIC KEY (commit to packages/gateway/src/updater/public-key.ts):
  base64: <PUBLIC-BASE64-44-CHARS>
  hex:    <PUBLIC-HEX-64-CHARS>

PRIVATE KEY written to:
  /tmp/nimbus-updater-key-XXXXXX/updater-private.b64

Upload to GitHub secret UPDATER_SIGNING_KEY, then delete:
  gh secret set UPDATER_SIGNING_KEY < "/tmp/nimbus-updater-key-XXXXXX/updater-private.b64" && rm -f "/tmp/nimbus-updater-key-XXXXXX/updater-private.b64"
```

Record both base64 values in your `nimbus-release-secrets` password manager entry.

- [ ] **Step 4: Update `public-key.ts` with the production base64**

Edit `packages/gateway/src/updater/public-key.ts` and replace `<DEV-PLACEHOLDER>` with the **public** base64 string printed in Step 3 (NOT the private key).

- [ ] **Step 5: Verify the file shape is correct**

```bash
grep UPDATER_PUBLIC_KEY_BASE64 packages/gateway/src/updater/public-key.ts
```
Expected: the line matches:
```
export const UPDATER_PUBLIC_KEY_BASE64 = "<PUBLIC-BASE64-44-CHARS>";
```
The base64 must decode to exactly 32 bytes (`echo -n "$pubB64" | base64 -d | wc -c` → `32`).

- [ ] **Step 6: Back up the private key file offline before uploading**

Copy the temp `.b64` file onto the same two USB drives used for the GPG master in Task 2 Step 7. The file content is short — keep the path short too, and label it clearly.

**Do not delete the temp file yet** — Task 6 reads it.
