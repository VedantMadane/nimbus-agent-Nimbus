# Review: v0.1.0 Release Implementation Plans

**Date:** 2026-05-05
**Reviewer:** Gemini CLI

---

## 1. Summary of findings

The implementation plans for `v0.1.0` are robust, granular, and well-sequenced. They successfully incorporate the recommendations from the design-spec review—most notably the avoidance of `setx` on Windows and the comprehensive version-alignment strategy.

There are a few minor technical inconsistencies and opportunities for improvement identified below.

---

## 2. Release Prerequisites (`v0.1.0-release-prerequisites.md`)

### Observations
- **Secret Naming Mismatch:** Task 6 and Task 11 use the name `UPDATER_ED25519_PRIVATE_KEY`. However, the existing scripts (`scripts/generate-updater-keypair.ts` and `scripts/sign-ed25519.ts`) expect `UPDATER_SIGNING_KEY`.
    - **Recommendation:** Standardize on one name. Since the scripts already exist, updating the plan to use `UPDATER_SIGNING_KEY` is the path of least resistance.
- **Lockfile Update:** Task 1 (version bump) should include a `bun install` step to ensure the lockfile reflects the root version change, even if it's a private package.

### Suggestions
- **Drafting Release Notes:** Add a small step in Task 15 to draft the GitHub Release notes (based on `docs/ROADMAP.md` Phase 4 items) rather than leaving it as a blank UI field.

---

## 3. Install Scripts (`cross-platform-install-scripts.md`)

### Observations
- **Robust Windows PATH:** Task 12 correctly implements the `.NET` API and broadcast logic, effectively mitigating the 1024-character truncation risk.
- **POSIX Portability:** The Unix scripts are well-structured for portability across `sh` and `zsh`.

### Suggestions
- **Shell Profile Cleanup:** In Task 11 (`uninstall.sh`), if stripping the Nimbus block leaves the file empty or with only whitespace, consider if it should be removed (optional, but cleaner).
- **WSL Consideration:** If a user runs the Linux installer inside WSL, it will update the Linux `PATH`. Since Nimbus is often used in cross-platform dev environments, a small note in the troubleshooting or install guide about WSL/Windows PATH interoperability might be helpful.

---

## 4. User Guide & Domain (`user-guide-and-custom-domain.md`)

### Observations
- **Infra Readiness:** The CNAME and `base` path changes are correctly identified and sequenced.
- **Deploy Smoke Test:** Task 21 is an excellent addition to ensure the custom domain is live before considering the task complete.

### Suggestions
- **Global Link Audit:** In addition to Task 3 (Doc sweep), add a task to check `packages/ui/` and `packages/cli/` for any hardcoded strings pointing to `asafgolombek.github.io` (e.g., in "About" dialogs or CLI help text).
- **Search Metadata:** For the new MDX pages, ensure `keywords` or `tags` are added to the frontmatter to help Astro Starlight's internal search provide better results.
